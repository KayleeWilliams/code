## Design Context

### Users

This fork is for the maintainer, a small engineering team, organization members, and friends who want a practical web GUI for coding agents. Users are developers working in active repositories, often juggling worktrees, PRs, AI review feedback, and agent failures.

### Brand Personality

Clean, configurable, smart, with a slightly playful edge. The app should feel professional enough for shared team use, but more personal and expressive than generic AI coding dashboards.

### Aesthetic Direction

Minimal, dense, and app-like. Use neutral surfaces by default, precise spacing, clear information hierarchy, and restrained pink/purple accents. Customization should carry most of the personality: font choice, accent color, theme mode, and optional playful details. Light and dark modes should both feel first-class.

### Design Principles

1. Workflow controls should be obvious, predictable, and recoverable.
2. Errors should appear in context, inside the chat workflow, with a clear repair action.
3. Customization should be powerful without making the default theme loud.
4. Prefer durable settings and typed contracts over local one-off UI state.
5. Keep performance and reliability ahead of decorative UI.
